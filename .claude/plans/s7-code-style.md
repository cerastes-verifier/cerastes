# S7 — cerastes's tool code in the owner's Boost style (handoff question 146)

## Context

The owner's directive is in handoff §8, question 146, answered "Follow recommendation" on 2026-11-05 and widened at this
planning. vlibc and vlibm already use the owner's Boost libraries' style (int128, decimal, charconv). cerastes's own tool
code does not yet: about 44,300 lines in `src/` and `include/`, written in 2-space K&R with unbraced one-line `if`s and
`T *p`. S7 moves it to that style in one session of its own:
- **When:** M4.5d2v has merged (`origin/main` = local `main` = `aa488d8`, no open branches), and M4.5d2b has not
  started. A whitespace-wide refactor conflicts with any parallel branch, so S7 must merge before d2b branches.
- **Outcome:** the whole tree is restyled, a `check.sh` step keeps it that way, and a proof shows that no behaviour
  changed. No user-visible behaviour changes. No test, expectation or golden changes.

**Owner answers at planning (2026-11-05).** Record them in handoff §8 as questions 147–149, with 146's "Follow
recommendation":
- **147. Full style sweep.** S7 does more than clang-format's layout. It also applies the three rules clang-format
  cannot: brace initialization, `U` on unsigned literals, and one declarator per declaration. The handoff's "mechanical"
  wording is widened accordingly.
- **148. The pinned clang-format comes from PyPI.** Use the official `clang_format` wheel, version **23.1.3** (the newest
  at least two weeks old), one wheel per platform (macOS arm64, manylinux x86-64). bootstrap downloads it with a pinned
  SHA-256, as it does Z3. This replaces the handoff's "Homebrew LLVM's" source: Homebrew's llvm floats (23.1.1 here) and
  Ubuntu 26.04 has only clang-format-21, so the two CI jobs would disagree.
- **149. Lambda bodies are Allman.** `{` goes on its own line, as in decimal's lambdas.

## Part 1 — Tooling (S1 and S2 in parallel), commit C1

S1, tooling:
1. **`.clang-format` at the root.** The starting configuration is below. S1 checks it against the exemplars and adjusts
   it; the reviewer confirms.
   - `BasedOnStyle: LLVM`, `Standard: c++20`, `ColumnLimit: 120`, `IndentWidth: 4`, `ContinuationIndentWidth: 4`,
     `UseTab: Never`.
   - `BreakBeforeBraces: Custom`:
     - braces on their own line after classes, structs, unions, enums, functions and control statements (`Always`);
     - braces on their own line before `else`, `catch` and lambda bodies;
     - attached after namespaces, `extern` blocks and case labels.
   - `InsertBraces: true`.
   - `PointerAlignment: Left`, `ReferenceAlignment: Pointer`, `DerivePointerAlignment: false`.
   - `IndentCaseLabels: true`, `AccessModifierOffset: -4`, `NamespaceIndentation: None`, `FixNamespaceComments: true`,
     `IndentExternBlock: NoIndent`.
   - **`SortIncludes: Never`**, because EDG headers depend on include order. `IncludeBlocks: Preserve`.
   - **`BreakStringLiterals: false`**, `ReflowComments: IndentOnly`, `IndentPPDirectives: Leave`.
   - `AllowShort*` set to `Never`/`false`, except `AllowShortFunctionsOnASingleLine: Empty` and
     `AllowShortLambdasOnASingleLine: Empty`.
   - `SpaceBeforeParens: ControlStatements`, `SpaceBeforeCpp11BracedList: true` (gives `T x {e};`).
   - `QualifierAlignment`, `RemoveParentheses` and `RemoveSemicolon` keep their defaults (off). The only option that
     changes tokens is `InsertBraces`.
2. **Guards.** Add `.clang-format` files with `DisableFormat: true` in `tests/`, `doc/` and `third_party/`, plus a
   `.clang-format-ignore`. Formatting a test, a doc example or an EDG or vlibc file from any IDE must change nothing:
   test lines are expectations.
3. **Pin.**
   - `bootstrap.sh` gains `CLANG_FORMAT_VERSION=23.1.3` and per-platform wheel URL and SHA-256 values (the digests come
     from PyPI's JSON and are checked on download).
   - It unzips `clang_format/data/bin/clang-format` into `build/tools/clang-format-23.1.3/`, asserts `--version`, and
     dies in `--build-only` mode when the binary is missing.
   - `env.sh` gets `CERASTES_CLANG_FORMAT`.
   - Record 0001's pin table gets the row.
4. **`scripts/format.sh [--check]`.**
   - It formats the file list above in place, from `git ls-files`, with the exclusions.
   - `--check` uses `--dry-run --Werror` and names each file that differs.
   - It must pass `shellcheck` and run in both CI jobs.
   - The `check.sh` step (`scripts/format.sh --check` in "lint") lands in C2. Before the layout pass it would fail.

S2, the proof tool. **`scripts/object_identity.py --before <rev|dir> [--after <rev|dir>]`:**
- It exports `src/` and `include/` of each side with `git archive` into `build/s7/<rev>/`.
- It takes each cerastes TU's command from `build/cmake/compile_commands.json`, with the repository root rewritten to the
  exported tree. EDG paths and generated headers stay where they are.
- It appends `-g0 -DNDEBUG -o <side>/<tu>.o` and compiles both sides with the same compiler.
- It requires the objects to be byte-identical. As a fallback for a difference that is not in the code, it compares
  `llvm-objdump -d -r -s` output. It names every TU that differs.
- It must cover every TU. If the count of TUs in `compile_commands.json` that are under `src/` changes, the tool fails.

S2, the self-test (`scripts/test_object_identity.py`, added to check.sh's harness self-test step):
- These cases must pass: a whitespace-only change, an inserted brace pair around a single statement, `n == 0` becoming
  `0U` where `n` is `std::size_t`, and `int x = 5;` becoming `int x {5};`.
- These cases must fail:
  - a changed literal;
  - `x - 1` becoming `x - 1U` where `x` is `int`;
  - `std::vector<int> v(3, 0)` becoming `{3, 0}`;
  - an `explicit` constructor chosen by brace-init over a converting one;
  - an `else` rebound;
  - a backslash-continued `//` comment that swallows the next line.
- Part 0 sanity check: compiling the same commit twice gives identical objects.

S2, the **sweep helper**: one-time, kept in `build/s7/` and not committed, described in record 0051.
- It reads clang's JSON AST (`-Xclang -ast-dump=json`) for each TU and keeps only locations that are spelled in an owned
  file and are not inside a macro expansion.
- **The `U` class:** an unsuffixed, non-negative `IntegerLiteral` directly under an `ImplicitCastExpr` `IntegralCast` to
  an unsigned type, or the right operand of `<<` or `>>`.
- **The brace class:** a `VarDecl` or `FieldDecl` with copy-initialization (`init: "c"`). It is rewritten from `= e` to
  `{e}`, and `= {…}` to `{…}`. These are excluded:
  - lambdas (keep `=`, as in the exemplars);
  - structured bindings;
  - default arguments;
  - range-`for` declarations.
- **Declarators:** Homebrew's `clang-tidy` (one-time, not pinned) with `readability-isolate-declaration` fix-its.
- It deduplicates by file offset across TUs and template instantiations, and accepts a list of owned paths so that the
  three agents never edit the same file.

C1 also holds record **0051-code-style.md** (a draft). It covers:
- the style;
- the configuration and its exclusions;
- the brace-init and `U` rules and their exceptions;
- the proof (object identity, then output identity);
- the `check.sh` step;
- `.git-blame-ignore-revs`;
- citations of source lines from before S7.

## Part 3 — Layout (S3 for fixups, reviewer round 1), commits C2 and C3

1. Run `scripts/format.sh`. Nothing else goes in C2. Gates:
   - `format.sh --check` is green;
   - `object_identity.py --before C1` reports **every TU identical**;
   - the build passes.
   - If any object differs, **stop**: find the cause (for example `InsertBraces` inside a macro), and do not edit
     around it.
2. **S3's hand fixups (C3).** Each fixup is followed by `format.sh`, and C3 must be object-identical to C2.
   - Trailing comments that force odd breaks move above their line.
   - Preprocessor directives inside functions are indented to the code's level.
   - `// clang-format off` is used only where a table needs it, with the reason beside it.
   - The stale comment in `register_attributes.h` ("eight attributes") is fixed; S6 listed it.
3. **Reviewer round 1** runs before C2 and C3 are committed (CLAUDE.md's protocol for diffs to `src/backend`,
   `src/viper`). It does not read the 69k-line diff. It audits:
   - the configuration against the exemplars and the vlibc text;
   - the guards;
   - `format.sh` and the pin;
   - **whether `object_identity.py` proves what it claims**: its flags, its TU coverage, its self-test cases;
   - the identity evidence;
   - a sample of the diff in each directory.
4. Take the blocking and should-fix items. Commit C2 (pure clang-format output, with the `check.sh` step) and C3.

**Split point (pre-agreed):** C1–C3 stand alone. If Part 4 cannot reach object identity, or the context runs short,
stop and ask. The layout merges as S7a, and the sweep becomes S7b.

## Part 4 — The full sweep (S1, S2 and S3 in parallel by directory), commits C4a–C4c

All three agents work in the one worktree and edit only their own paths. Each agent, in order:
1. Runs the helper's three classes on its paths: declarators, `U`, braces.
2. Fixes the residue by hand:
   - Narrowing errors get `static_cast<T>(e)` inside the braces. That is the same conversion as before.
   - Macro-spelled sites are left alone and listed.
   - Declarations whose type has an `initializer_list` constructor, or an `explicit` constructor, are checked by hand.
3. Runs `scripts/format.sh`.
4. Compiles its TUs.
5. Runs `object_identity.py --before C3` on its TUs. **Every TU must be identical.** A difference is reverted. It is
   never explained away.

The agents do not commit. The main session checks the whole tree's identity against C3 and commits once per agent
(C4a backend and driver, C4b vir, C4c viper and include). The headers belong to their directory's agent.

**Reviewer round 2** audits:
- the rules and exceptions against the owner's text and the exemplars;
- the helper's classes, including whether any site that changes meaning could pass object identity;
- the residue list and the hand-edited sites;
- a sample from each directory.

A re-audit covers the blocking fixes only.
